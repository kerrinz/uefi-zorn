# 上游更新后的固件依赖与回归

日期：2026-10-29。整机工作按构建回归、触控、CPU 稳定性及其他外设的顺序推进，GPU 后置。本轮没有重建或替换已验证 FD，没有刷写手机。

主仓库更新到 `066c8d8` 后，独立 XNU 源码的 157 个补丁两次干净重放通过，1011 个新对象及预链接成功。保留现有组件版本、同一触控供电 FD、8 核、保留 Data、低亮度和快采样，完整打包为 `0b4eda46`，127 项输入与完整归档已核对，首次回收在 CPU1 预检 `SMP261` 退出，没有进入用户态；旧基线同起点对照已由机主再次确认桌面和图标点击正常。新候选第二次通过八核但仍是苹果标志，不能替换旧基线。

本仓库仅修正供电宿主审计的路径标识：对实际 DXE 文件调用 `resolve()`，消除工作区搬迁与依赖符号链接造成的路径差异。文件哈希、协议槽、供电参数、实际头文件的 ASan / UBSan 测试都保留。搬迁后结果与原 FD 的能力记录完全一致，不需要伪造能力记录或放宽比较。

原已验收默认镜像 `42f3d518` 保留，新候选尚未按旧结果宣称桌面 / 触控通过。编译仍显式使用历史 ABI fixture，不称为仅凭源码和 IPSW 的完整 bootstrap。详细记录维护于相邻设备仓库的 `docs/progress-2026-10-29-repro-build.md`；发布后可通过 [设备仓库记录](https://github.com/kerrinz/UniXNU-zorn/blob/main/docs/progress-2026-10-29-repro-build.md) 查看。

## 后续受控对照

旧公开补丁集的独立新对象 `1e926696` 通过八核但未验收桌面。进一步固化实际成功工作树，97 个源码文件在固定 SMP 转换后逐字节一致；独立编译候选 `2b4b143c` 完成 221 项输入检查，两次回收均在 CPU1 `SMP261 / START1 step4 rc0` 退出。

1024 个对象的指令段与保留工作区一致；差异仅工作区路径字符串和编译时间，最终原生符号整体后移 `0x4000`。正在用只规范化路径的新对象对照排查布局影响，尚不称其为 CPU 修复。固件 FD、触控供电、亮度和自动回收策略保持原样；此轮无需重建 UEFI。

路径规范化的新对象候选 `3a8ac966` 的九个复位相关符号地址及最终复位向量与旧基线一致，机主已确认桌面和图标点击正常；首轮新日志已绑定：八核掩码ff、Data保留、亮度读回64、触控无坏帧或提交错误；第二轮也通过八核并由机主确认桌面，已绑定新日志。双指解码同时保留两个ID约5.2秒且正常释放，尚不等于系统捏合手势验收。尚不把它称为 CPU1 根因修复，默认镜像保留旧基线。
