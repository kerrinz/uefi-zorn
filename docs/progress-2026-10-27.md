## 固件已验证部分

- BootShim → Mu-Silicium UEFI → UniXNU 菜单 → DarwinBoot → XNU 的交接已完成。
- GOP/framebuffer 为 1440×3200、32 bpp、stride 5760 字节。
- 固件 FD 位于 `0xA7100000`，大小 `0x300000`；内核解压窗口为 256 MiB。
- ZornBootMemoryDxe 发布 ZORNESP；192 MiB FAT32、512 字节簇可被 EDK2 挂载。
- 菜单读到 `EFI/UniXNU/unixnu.toml`，标题 Redmi K80，倒计时 5 秒。
- 当前 DarwinBoot 已能交接原版 trust cache sidecar。

本轮复用了原先验证过的 FD，更新重点是负载配置、trust cache 打包、内核及诊断。
SM8650 的 giulia 二进制依赖仍由外部 Mu-Silicium 检出提供；本仓库不包含这些输入。

## 当前整机阶段

UFS 读盘、userdata 上的只读 OS APFS 根、原版 trust cache、exec 签名检查、
init exec 返回和 EL0 运行都已验证。补齐 PAN 配置后，用户拷贝、Mach VM 分配
及第 32 次 SVC 检查点通过，已读到 PID1 的 Darwin Ignition/libignition 文本。
原版 PMGR nub 的生命周期与服务发布已通过，完整硬件电源功能尚未实现。

当前自然停止在 `security.mac.img4.ignition_blob`：MAC 检查返回成功，进入
原版 AppleImage4 处理函数 `0xfffffff004a948ec` 后没有观察到返回。
55 秒独立 watchdog 会自动回 recovery。当前菜单目标第 64 次 SVC 尚未达到。

尚未进入 launchd 主循环或桌面。SystemOS 虽然已在 userdata 镜像中，单独发布、
挂载和启动链验证尚未接通；可写 Data、完整图形、触控及其他板级外设也待完成。
